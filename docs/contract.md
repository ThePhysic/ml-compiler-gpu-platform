# Historical engineering contract

This document preserves the component interfaces agreed during the initial parallel implementation. Coordination assignments have been reframed as an interface reference; their original wording remains in Git history. It is historical design context, not a current task list or the authoritative numerical contract. See [architecture](architecture.md), [compiler](compiler.md), [simulator](simulator.md), and [kernels](kernels.md) for current behavior, precision rules, backend limits and later audit fixes.

## IR and numerical reference

`mlgpu.ir` supplies dataclasses `TensorSpec(shape: tuple[int,...], dtype: str='float32')`, `Node(op: str, inputs: tuple[str,...], output: str, attrs: dict = {})`, `Graph(inputs: dict[str,TensorSpec], nodes: list[Node], outputs: tuple[str,...], constants: dict[str,np.ndarray] = {}, name: str='graph')`.

TensorSpec has `.numel`, `.nbytes`, `.strides` (contiguous element strides); `Graph.validate()` returns self; `Graph.specs()` returns every value's TensorSpec; `Graph.ordered_nodes()` returns dependency-valid nodes (input list order need not be topological); `Graph.to_dict()` and `.format()` inspect IR. All shapes positive, rank >=1, float32 or float16, row-major contiguous. Op names: matmul (2D), add/mul (NumPy broadcast), relu/gelu (tanh approximation), softmax (last axis), layernorm (last axis, inputs x, weight, bias; epsilon attr `eps`), reshape (`shape` attr), transpose (`axes` attr, materialized contiguous), sum (`axis` attr int; `keepdims` bool, default true), identity. No dtype promotion. Fused ops: `fused_matmul` inputs a,b[,bias], attrs activation='none'|'relu'|'gelu'; `fused_elementwise` accepts an SSA region in attrs `steps`: list dicts {op,inputs,output,attrs}; steps may use graph external inputs and preceding intermediates, final output equals Node.output. Fusion preserves intermediate FP16 rounding semantics: fused kernels round intermediate operations to output dtype before proceeding. Matmul reference uses FP32 accumulation followed by cast; sum/normalization reduce in FP32, output cast.

`mlgpu.reference.evaluate_node(node, values)` returns a contiguous NumPy output. `execute(graph, inputs)` returns dict of graph output names to NumPy arrays, enforcing exact input names/shapes/dtypes. `mlgpu.errors` supplies GraphError, CompileError, ResourceError, ExecutionError, BackendUnavailable (all subclass PlatformError).

## Compiler interface

Implemented in `src/mlgpu/compiler.py`, with verification in `tests/test_compiler.py` and design notes in [compiler.md](compiler.md): `compile_graph(graph, optimize=True, memory_budget=None) -> ExecutionPlan`; plan `.graph` optimized Graph, `.nodes` scheduled list[Node], `.memory` MemoryPlan, `.passes` list[dict] change summaries, `.tiles` dict output name -> config {block_m,block_n,block_k,num_warps}. MemoryPlan `.allocations` dict tensor -> Allocation(offset,size,start,end), `.peak_bytes` arena bytes, `.naive_bytes`, `.to_dict()`. Inputs/constants remain external; produced graph outputs are allocated in the arena and pinned through completion, while direct input/constant outputs remain external. Nonaliasing lifetimes inclusive at op execution; input during op cannot share its output. Alignment 256 bytes; reuse by best fit. ExecutionPlan `.to_dict()` and `.format()`; original graph untouched. memory_budget enforced in bytes. Fusion max 16 steps (runtime limit) and last output only, intermediate nodes must have one consumer and not be graph outputs. Scheduling dependent deterministic peak-aware ordering.

## Simulated-accelerator interface

Implemented in `src/mlgpu/simulator.py`, with verification in `tests/test_simulator.py` and assumptions in [simulator.md](simulator.md): `HardwareConfig(...)` with JSON-able `.to_dict()` and coherent compute/transfer/local-memory resources; `compile_simulator(graph, hardware=None, optimize=True) -> SimulatorPlan`; plan `.to_dict()` and `.format()`. `simulate(plan, inputs) -> dict outputs` executes actual emitted tiled instructions, not reference graph. `estimate(plan)` returns explicitly modeled costs; schedule enforces dependencies, banks, local-memory capacity and compute/transfer contention. This backend can use the shared compiler pipeline and has no GPU dependency. Required demonstrations cover matmul-bias-activation, normalization with elementwise operations, and a two-layer MLP. Unsupported simulator ops may have bounded generic instructions but must implement numerical semantics and honest cost assumptions. Resource errors explicit. Baseline optimize=False versus optimize=True must affect instructions, transfers, memory or modeled cost.

## Triton backend interface

Implemented in `src/mlgpu/gpu/`, with verification in `tests/test_gpu.py`, readiness checks in `scripts/probe_gpu.py` and design notes in [kernels.md](kernels.md). GPU imports are lazy, so CPU compilation, reference execution and simulator tests do not require PyTorch/Triton. `ensure_available()` and `launch(node, inputs: list[torch.Tensor], output: torch.Tensor, config: dict|None=None)` in `mlgpu.gpu`; writes output and returns None. Every supported graph op above lowered to original Triton kernels, no PyTorch arithmetic fallback. Tensor inputs/outputs contiguous, float16 or float32. Matmul inputs 2D. Shape tails masked; transpose/reshape/identity materialized copies. Kernel study variables include configurable matrix tiles/warps, explicit FP16 materialization semantics in fused epilogues and elementwise chains, tests of irregular/numerically challenging inputs. Matmul uses ieee input precision for FP32, no silent TF32. Benchmark interface may expose individual functions but graph `launch` required. Primary Triton/PyTorch references are linked from the kernel documentation. Development used WSL2 Ubuntu and an RTX 4060 Laptop GPU; this does not imply native Windows Triton support. Current prepared-dispatch APIs and audited numerical limits are documented in [kernels.md](kernels.md).
